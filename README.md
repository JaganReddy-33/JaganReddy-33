> **The interesting problem isn't booking a seat.**
>
> **It's deciding what happens when 100 requests try to book the same seat.**

</div>

<br/>

### 🧠 The Engineering

**Atomic booking**

MongoDB performs the availability check and state transition atomically, eliminating the classic read → check → write race.

**Idempotent requests**

Retries and duplicate clicks don't create duplicate bookings.

**Real-time state**

Socket.IO propagates booking changes to connected clients immediately.

**Secure access**

JWT authentication with role-based organizer authorization.

**Concurrency proof**

Custom load testing was used to simulate competing booking requests rather than assuming the implementation was safe.
